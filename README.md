# ホイールアライメント計測 PWA（並進基準法 v2・低速対応）

スマホの IMU（加速度・ジャイロ）だけで**キャンバー**と**トー（相対）**を計測する PWA。
**磁気センサ不使用**。GitHub Pages 前提（全相対パス・`.nojekyll`・相対SW登録）。

## v2 での変更点（「ゆっくり動かせない」問題の解決）

実機で「短く強く押す」のが厳しいという課題に対し、**2つの物理的原因**を突き止めて対処しました。

1. **端末スピンの塗り潰し（本命）**: 端末はホイールと一緒に回転する（車が20cm進むとタイヤ径30cmで約38°回転）。
   旧v1は加速度PCAで並進方向を取っていたため、押しが長い＝回転が大きいほど方向が塗り潰されて破綻していた。
   → **スピン角 φ=∫(ω·ŝ)dt を積分し、線形加速度を逆回転して安定フレームへ戻す**（スピン補正）。
2. **低速のSNR**: ゆっくり動かすと加速度が小さくノイズに埋もれる。
   → **速度・変位に積分して向きを取る**（積分が平均化に働き低速に強い）。加えて
   **ZUPT**（押しの開始/終了は静止という前提で速度を線形デトレンド）でバイアスドリフトを除去。

**直進ゲートも刷新**: 「最小移動量（既定5cm）」＋「軌跡の曲がり角上限（既定2°）」で判定（スケール非依存）。
UX は「**② 押し開始 → ゆっくり転がす → ③ 停止＆判定**」へ変更。前進して止める／前進して戻す、どちらでもOK
（最遠点方向を進行方向として採用）。

### 検証（`_test_v2.js`, Node）
- 端末スピンを**含む**合成データで、ゆっくり(0.15 m/s²・4秒, スピン114°)・強い(1.4・1秒)双方でトーを復元。
- ノイズ無しでトー誤差 < 0.004°、曲がり 0.000°（パイプライン厳密）。
- 現実ノイズ＋床オフセットσ0.3°のモンテカルロで、平均回数によりトーRMSが
  **1回0.42° → 3回0.24° → 5回0.17°(2.2mm) → 10回0.11°(1.4mm)** と収束（シミュレータ予測と一致）。
- 参考: 同じゆっくりデータに旧v1を当てると測toe≈-178°で破綻（スピン塗り潰し）。

## 既存デプロイの更新方法（差し替え）
既に GitHub Pages で公開済みなら、**以下を上書きコミット**すれば反映されます（SWのCACHE名をv2にしたので、
再訪問時に旧キャッシュが破棄され自動更新）。
- 必須: `estimator.js`, `app.js`, `index.html`, `sw.js`
- 推奨: `manifest.webmanifest`, `styles.css`, `README.md`
- 変更なし: `sensors.js`（同等）, `icons/*`

```bash
git add .
git commit -m "v2: spin-corrected translation reference (low-speed friendly)"
git push
```
更新後、スマホでページを一度リロード（スタンドアロン起動なら再起動）すると v2 が有効になります。

## GitHub Pages 公開（新規の場合）
1. リポジトリ直下に一式を置く（`index.html` がルート）。
2. Settings → Pages → Source: Deploy from a branch, Branch: `main` / `/(root)`。
3. `https://<user>.github.io/<repo>/` で公開（HTTPS自動）。

> サブパス配信でも動くよう、manifest/SW/スクリプトは全て `./` 相対、SW登録は
> `register('./sw.js', {scope:'./'})`。`.nojekyll` で `_test_*` 等も配信（不要なら削除可）。

## 使い方（実機）
1. Android Chrome で公開URLを開く（HTTPS必須）。**権限 → センサ起動**。`mode`/`実効Hz` を確認。
2. 対象輪を選び、治具で端末をハブ中心へ固定。
3. **① 静止取得**（1.5秒）。
4. **② 押し開始** → 床ガイドに沿って**ゆっくり数十cm**転がす（急がなくてよい）。
5. 止めたら **③ 停止＆判定**。移動量・曲がりが表示され、ゲート通過なら採用。
6. 採用回数に達したら次の輪へ。4輪完了で総トー・スラスト角・スラストライン基準トーを表示。
7. **CSVエクスポート**（結果＋生ログ）。後処理は Python で。

### 精度の勘所
- スイートスポットは **曲がり上限2° × 移動量5cm以上 × 採用3〜5回**。
- **絶対トーの一発値より、同一治具・同一場所での相対トー（調整前後差・左右差）**が高再現性。
- 誤差の下限は「床オフセット（真っ直ぐだが角度付き）」が決める → **床ガイド・停止手順の統一**が最重要。
- ゆっくり長い押しは積分ノイズが増えるので、**移動量を確保（10cm以上推奨）＋複数回平均**が効く。
